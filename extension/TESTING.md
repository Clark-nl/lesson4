# 테스트 방법

## 1. 압축해제된 확장 프로그램으로 로드

1. `chrome://extensions` → 개발자 모드 ON
2. "압축해제된 확장 프로그램을 로드합니다" → 이 `extension/` 폴더 선택
3. 툴바 아이콘 클릭 → 팝업 확인, 아이콘 우클릭 → 옵션으로 설정 페이지 확인

## 2. 실제 Gumroad 계정 없이 프리미엄 플로우 테스트하기

`isPremium`은 `chrome.storage.sync`에 저장되는 boolean 하나로 결정됩니다. 실제 결제 없이도 이 값을 직접 켜서 프리미엄 UI/기능을 전부 테스트할 수 있습니다.

1. `chrome://extensions` → 이 확장 프로그램 카드에서 "서비스 워커" 링크 클릭 (DevTools 콘솔이 열림)
2. 콘솔에 아래 입력 후 Enter:
   ```js
   chrome.storage.sync.set({ isPremium: true })
   ```
3. 팝업/옵션 페이지를 다시 열면 프리미엄 UI(뱃지, 커스텀 타이머, 통계, 도메인 그룹핑, 자동 정리)가 모두 열립니다.
4. 다시 무료 상태로 되돌리려면:
   ```js
   chrome.storage.sync.set({ isPremium: false })
   ```
   또는 옵션 페이지의 "라이선스 비활성화" 버튼을 누르면 됩니다.

이 방법으로 아래 항목까지 실제 Chromium에서 자동화 테스트(Playwright)로 검증했습니다:

- 팝업 초기 상태(타이머 25:00, 뱃지 숨김, teaser 통계 노출)
- 중복 탭 닫기 (실제 `chrome.tabs.remove` 호출 확인)
- 타이머 시작 → 카운트다운 → 일시정지 → 재개 → 리셋
- 옵션 페이지 무료 상태 잠금(입력 비활성화, 안내 문구) → 프리미엄 전환 시 잠금 해제
- 커스텀 타이머 저장 후 팝업에 반영 (예: 50분 설정 → 팝업에 50:00 표시)
- 프리미엄 전용 "도메인별 그룹핑" 실행 → 실제 `chrome.tabGroups` 생성 확인
- 빈 라이선스 키 입력 시 클라이언트 검증 메시지
- 라이선스 비활성화 → 무료 상태 복귀

## 3. 실제 Gumroad 라이선스 검증 테스트하기

이 샌드박스 환경은 조직 프록시 정책상 `api.gumroad.com`으로 나가는 아웃바운드 요청이 막혀 있어 실제 API 응답까지는 이 세션에서 검증하지 못했습니다. 대신 네트워크 요청이 실패하는 상황(위와 동일한 종류의 차단)을 실제 브라우저로 재현해서, 예외 없이 사용자에게 "검증 서버에 연결하지 못했습니다. 인터넷 연결을 확인해주세요." 메시지가 뜨는 것까지는 확인했습니다.

일반 인터넷 환경(사용자의 실제 PC)에서는 프록시 제약이 없으므로 정상적으로 Gumroad API에 도달할 것으로 예상되지만, 아래 절차로 실제 유료 흐름을 한 번은 직접 검증하는 것을 권장합니다.

1. `lib/premium.js`의 `GUMROAD_PRODUCT_PERMALINK`를 실제 상품 permalink로 교체
2. Gumroad 상품 설정에서 "Generate a unique license key per sale"을 켜고, 테스트 결제(또는 100% 할인 쿠폰)로 라이선스 키 1개 발급
3. 옵션 페이지에서 그 라이선스 키를 입력해 "활성화" 클릭
4. 성공 메시지("프리미엄이 활성화되었습니다...")와 함께 프리미엄 UI가 열리는지 확인
5. Gumroad 대시보드에서 해당 라이선스를 환불 처리한 뒤, 같은 키로 새 세션에서 활성화를 시도해 실패 처리(`refunded` 체크)가 되는지도 확인해두면 안전합니다.

## 알려진 제약 (판매 전 인지해야 할 부분)

- 프리미엄 여부는 클라이언트(로컬 storage) 판단이라, 이론적으로 위 콘솔 명령을 아는 사용자는 무료로 잠금을 풀 수 있습니다. 서버 검증이 없는 단일 익스텐션 구조에서는 흔한 트레이드오프이며, 완전히 막으려면 자체 백엔드로 매 세션 검증하는 구조가 필요합니다 (템플릿 구매자가 원할 경우 확장 가능한 지점으로 `lib/premium.js`에 안내 남겨둠).
